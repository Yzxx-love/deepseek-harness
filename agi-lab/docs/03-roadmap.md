# 路线图

本文定义 `agi-lab` 的 M0–M5 里程碑、每个里程碑的可测量退出条件（gate）、风险与非目标。架构事实以 [02-architecture](02-architecture.md) 为准，评测口径以 [04-evaluation](04-evaluation.md) 为准，安全边界以 [05-safety-and-alignment](05-safety-and-alignment.md) 为准。

## 1. 阅读规则

- **不写日期。** 里程碑只由依赖关系与 gate 决定先后；任何"预计某月完成"的表述都不属于本文件。
- **gate 必须可执行、可归档。** 每条 gate 都能对应一条命令、一份报告或一个可检查的代码事实；写不出证据的条款不是 gate。
- **gate 不能追溯放宽。** 未通过就保持未通过；可以补充说明、拆分后续工作，但不能为了宣布完成而降低阈值。若确需改口径，先改 04 并记录原因，再按新口径重跑。
- **状态词与 02 一致。** 能力分级的状态（已实现 / 机制已实现收益待验证 / 仅预留脚手架 / 不在范围）以 02 的"能力分级"表为准，本文件不另立一套。
- **架构变更回写 02。** 里程碑若改变分层、模块、契约或安全模型，必须同步更新 02；只改路线图不改架构文档视为文档缺陷。

## 2. 能力阶梯推进表

本表只写"推进路径与验证方式"；L0–L5 的定义与当前状态见 [02-architecture](02-architecture.md) 的"能力分级"，不在此重复。

| 级别 | 所需新增能力 | 对应里程碑 | 怎么验证 |
|---|---|---|---|
| L0 工具调用器 | 无（已覆盖） | M0 | 机制测试覆盖单轮工具调用、参数错误与格式失败路径；真实模型下作为 M1 能力套件的一部分 |
| L1 计划执行者 | 显式分解、依赖执行、失败后重规划 | M0（已实现） | M0 的 G0.3 机制路径 + M1 的真实模型任务成功率、步数与重规划指标 |
| L2 记忆学习者 | 四层记忆、跨任务检索、教训注入 | 机制 M0；**收益 M2** | M2 的同任务族配对消融：Δ步数、Δ成功率、成本开销，见 04 的"记忆迁移增益" |
| L3 自主研究体 | 自设子目标、长时运行、预算自管理、主动求助 | M3 | M3 的 G3.1–G3.6：长任务、ASK、checkpoint、预算申请、安全回归 |
| L4 跨域迁移者 | 未见任务族上接近人类可靠性、少样本掌握新技能 | 不在实现范围 | 无可信验证设计，不写能力声明 |
| L5 超人类通用 | 多域显著超越人类专家并可自我改进 | 不在实现范围 | 定义本身有争议，不写能力声明 |

推进纪律：L2 的机制在 M0 落地，但**在 M2 之前，L2 一律表述为"机制已实现，收益待验证"**；L3 在 M3 之前一律表述为"仅预留脚手架"。级别状态只在对应 gate 通过后由 02 更新，其余文档不得抢先改词。

## 3. 里程碑总览

依赖关系（箭头表示"完成后才能开始"）：

```
M0 ──► M1 ──► M2
 │      │      │
 └──────┴──────┴──► M4 ──► M3 ──► M5
```

顺序原则：**评测先于能力（M1 先于任何能力声明）、收益验证先于范围扩张（M2 先于 L3）、安全门槛先于自主性（M4 先于 M3）、外部复现最后（M5）**。

| 里程碑 | 主题 | 依赖 | 完成后阶梯状态 |
|---|---|---|---|
| M0 | 当前实现：离线可运行基线（L1 完整 + L2 机制） | 无 | L1 已实现，L2 机制已实现、收益待验证 |
| M1 | 真实模型能力基线 + 评测台 v1 | M0 | L0–L1 有真实模型基线数据 |
| M2 | 记忆迁移收益验证（L2 完成判据） | M1 | L2 可按结果升级或维持"待验证" |
| M4 | 安全与鲁棒性门槛 | M1、M2 | 安全模型经过红队回归，可支撑更大自主性 |
| M3 | L3 脚手架：半自主长任务 | M2、M4 | L3 部分实现（仅限脚手架的已验证部分） |
| M5 | 外部可复现与发布候选 | M3、M4 | 外部可复现的发布候选 |

## 4. M0 当前实现：离线可运行基线（L1 完整 + L2 机制）

**目标。** 在无 API key、无网络、零第三方依赖的条件下，完整跑通"计划—执行—评审—反思—重规划"循环，四层记忆真实写入并在后续运行中复用，所有动作可观测、所有失败可归因。这是项目的可运行基线，也是后续所有 gate 的回归底座。

**交付物。**

- 按 02 模块表落地的内核、llm、memory、tools、cognition、runtime、cli 模块（模块清单以 02 为准，不在此重复）。
- 双 provider：脚本化离线 `MockLLM` 与真实 OpenAI 兼容 provider，实现同一 `LLMProvider` 接口。
- CLI：`demo` / `run` / `tools` / `replay` / `config` 可用；`eval` 子命令已存在，评测模块属 M1 交付物（缺失时显式报错，退出码 2）。
- 四类离线演示任务（`agi_lab/demo.py`）：工具调用闭环、多步计划与文件读写、失败恢复与重规划、安全拦截与审计。
- 单元/集成测试：契约、格式解析、记忆持久化、路径围栏、审批拒绝、预算终止、mock 回放、循环检测。
- 文档 01、03、04、05、06 与 02 对齐的初版。

**退出条件（gate）。**

| 编号 | 条件 | 证据 |
|---|---|---|
| G0.1 | `python -m agi_lab demo` 在无 key、无网络时运行 4 个机制演示任务并全部 PASS（退出码 0）；每个任务目录 `runs/demo-<时间戳>-<id>/<task>/` 含 `trace.jsonl` 与 `report.md` | 命令输出 + 运行目录 |
| G0.2 | `python -m unittest discover -s tests` 为 0 failures、0 errors；skip 必须逐条列出原因 | 测试输出存档 |
| G0.3 | mock 脚本任务覆盖"一步失败 → 反思产出 lesson → 重规划 → 最终成功"，终态为 `RunStatus.SUCCESS` 且 `metrics.replans ≥ 1`、`metrics.lessons ≥ 1`；`RunResult.success` 保持 `False`，成功只由评测层外部 grader 赋值（契约见 `types.py`） | 集成测试与 trace |
| G0.4 | 第二个 run 的提示上下文含第一个 run 写入的 lesson（trace 可查）；进程重启后持久化记忆仍可检索（默认 `<state_dir>/memory/<kind>.jsonl`，见 `config.py` 的 `memory_dir`）；`MemoryHub` 注入有字符预算截断 | 测试 + trace |
| G0.5 | `../`、绝对路径越界、符号链接路径均被拒绝且记录安全事件；`approval_mode=deny` 下需审批工具不执行副作用；预算维度（步数 / 调用 / token / 墙钟）耗尽终态为 `BUDGET_EXHAUSTED`；重试、重规划等非预算上限触发时以 `FAILED` / `BLOCKED` 结束，且任一非 `SUCCESS` 终态都有非空 `stop_reason` | 安全与预算测试 |
| G0.6 | trace 每行是合法 JSON，事件类型足以重建执行顺序；`read_events` 能读取全部事件，`replay` 能渲染时间线 | trace schema 测试 |
| G0.7 | 同一 mock 脚本与 seed 运行两次，`Metrics` 的 steps/llm_calls/tool_calls/replans 完全一致 | 确定性测试 |
| G0.8 | 文档 01–06 与 02、代码无事实冲突；每个能力陈述都能落到 02 的状态词 | 文档评审记录 |

**风险。**

| 风险 | 影响 | 缓解 |
|---|---|---|
| 模块并行开发导致契约漂移 | 集成失败、返工 | `types.py` 全局冻结；任何契约变更先改 02 并通知全体 |
| mock 脚本与实现强耦合 | 机制测试只验证脚本而非循环 | mock 只按角色脚本队列应答；断言检查循环行为（重规划、预算、trace），不检查具体措辞 |
| 范围膨胀到评测台与能力对比 | M0 迟迟不收敛 | 评测台与真实模型基线明确属于 M1；M0 只做机制自检 |
| Windows 路径/子进程差异 | 演示在他机失败 | 开发与验证环境固定 Windows + Python 3.11；路径统一 `pathlib` + 解析后围栏 |

**Non-goals。** 不证明任何能力（无真实模型结论）；不做能力对比与排名；不实现评测台与 held-out 任务集（M1）；不做容器/VM 隔离（见 05）；不追求性能优化。

## 5. M1 真实模型能力基线 + 评测台 v1

**目标。** 把"评测先于能力"落成可执行设施：建立独立 grader、任务集、运行器与报告归档，用真实 provider 跑出第一份可复现的能力基线。此后任何能力声明都必须引用这份基线。

**交付物。**

- 评测台 v1：任务集（含 held-out 划分）、独立 grader、runner、报告生成与归档格式（见 04 的"结果归档格式"）。
- 能力套件 v1：≥10 个任务、≥3 个任务族，每任务独立 grader；任务不得出现在任何提示词示例中。
- 真实模型基线报告：逐任务成功率、步数、token 成本、失败清单；配置哈希固定。
- 缺失 API key 的行为规范：套件标记 SKIPPED 并以非零退出码结束，报告不得把跳过计为通过。

现状说明：仓库已有 `eval` 子命令的入口，但评测模块本身尚未实现（缺失时显式报错、退出码 2）；因此 M1 的第一项工作是补齐评测层，其余 gate 依赖它提供的数据。

**退出条件（gate）。**

| 编号 | 条件 | 证据 |
|---|---|---|
| G1.1 | 评测台能在无 key 时明确 SKIPPED（非 pass），有 key 时产出完整报告 | 两种模式的命令输出 |
| G1.2 | 能力套件 ≥10 任务、≥3 任务族、全部 held-out；grader 独立于 agent（不读取 agent 自评，不导入认知/记忆模块，只依据最终工作区与答案） | 任务集清单与 grader 源码评审 |
| G1.3 | 每任务 ≥3 次重复；报告给出成功率、步数、token 的均值与极差，并区分任务间与任务内方差 | 基线报告 |
| G1.4 | 第二位执行者在独立目录按文档复跑，结论方向一致；若不一致，M1 不通过并进入原因分析 | 复跑报告与差异说明 |
| G1.5 | 报告含成本（token 与墙钟），且**全部失败 run 的 trace 路径与归因公开**，无删除、无隐藏 | 报告附件 |
| G1.6 | M0 机制套件保持全绿；能力工作在 `mock` 下仍可离线回归 | 回归测试输出 |

**风险。**

| 风险 | 影响 | 缓解 |
|---|---|---|
| 任务集偏向 agent 强项 | 基线虚高 | 任务族覆盖不同类型；任务选择先于结果冻结；由非实现者评审 |
| 采样方差大，单次结论误导 | 误判能力 | 强制重复 ≥3；报告极差与失败分布；小样本只作方向性结论 |
| grader 被输出欺骗 | 分数造假 | grader 只认可验证产物；对"把答案写进文件"类作弊做专门红队用例 |
| 回放成本高 | 重复次数不足 | 固定默认预算与较小任务；只对关键任务增加重复 |

**Non-goals。** 不与其他框架/模型排名；不做训练或提示词大规模搜索（那会污染 held-out）；不宣称 L2 收益（M2）；不优化成本到牺牲可观测性。

## 6. M2 记忆迁移收益验证（L2 完成判据）

**目标。** 把 L2 从"机制存在"推进到"收益有证据"：在同一任务族、同一模型、同一预算下，用配对消融回答"注入既往教训是否减少步数或提高成功率"，并同时报告成本。

**交付物。**

- 预注册协议：假设 H1、主指标（配对步数差 Δsteps）、次指标（成功率差 ΔSR）、样本量、分析计划，在实验运行前落盘。
- 配对任务族设计：train 任务产生的教训注入 eval 任务；两臂（with-lessons / without-lessons）唯一差异是记忆注入。
- 消融报告：效应量、区间、成本开销、失败清单；聚合脚本与原始 run 归档。
- 结论落点：无论正负，更新 02 的 L2 状态说明（"收益已验证"或维持"待验证"），并在 04 记录口径。

**退出条件（gate）。**

| 编号 | 条件 | 证据 |
|---|---|---|
| G2.1 | 预注册协议先于实验落盘；运行后不得修改 H1、指标或分析计划 | 协议文件的时间戳与内容 |
| G2.2 | 每臂 ≥20 个配对样本（任务 × 种子），两臂任务、种子、模型、预算、提示词完全一致，唯一变量是教训注入 | 配置哈希与配对表 |
| G2.3 | 报告 Δsteps 与 ΔSR 的效应量与区间，并报告教训注入带来的额外 token 成本 | 消融报告 |
| G2.4 | 判定规则事先固定：Δsteps > 0 且区间不跨 0 才可声明"观察到收益"；否则结论必须是"未观察到收益"或"成本上升"，不得改挑子任务 | 结论与协议对照 |
| G2.5 | 教训只来自同任务族 train 划分；eval 划分未参与提示词调试或人工挑选；M0 机制套件保持全绿 | 数据流审计 |
| G2.6 | 第三方可用归档的原始 run 与聚合脚本重算出报告中的数字 | 重算记录 |

**风险。**

| 风险 | 影响 | 缓解 |
|---|---|---|
| 教训泄漏（eval 信息进入记忆） | 收益虚高 | 数据划分审计；记忆来源标注与可追溯 |
| 注入额外 token 造成不公平对比 | 把"更贵"误判为"更好" | 同时报告 Δtoken 与 Δsteps；必要时加入等成本对照 |
| 事后挑选有利任务族 | 结论不可信 | 协议预注册；全任务族结果必须全量报告 |
| 结论为负时的叙事压力 | 隐瞒负结果 | 04 的失败公开要求；负结论同样归档 |

**Non-goals。** 不做向量检索/嵌入（见 06 的 ADR-005）；不做在线学习或权重更新；不跨任务族外推结论；不把 L2 收益当作 L3 依据。

## 7. M4 安全与鲁棒性门槛

**目标。** 在扩大自主性之前，把安全从"设计条目"变成"有回归测试、有红队证据、有部署边界"的门槛。M4 的编号先于 M3，因为更大的自主性必须先有更硬的安全底座。

**交付物。**

- 红队套件：离线机制用例（必测）+ 真实模型对抗用例（提示注入、目标劫持、资源耗尽、数据外泄），并入常规回归。
- 威胁模型更新：05 的表格与实现逐条对照，残留风险显式列出。
- 审批完整性审计：所有 `requires_approval` 工具在默认拒绝模式下不可执行，且无别名/间接路径绕过。
- 部署边界文档：进程级 + 路径级沙箱的明确局限，生产需要的容器/VM/权限分离建议。

**退出条件（gate）。**

| 编号 | 条件 | 证据 |
|---|---|---|
| G4.1 | 05 中标记为"必须阻断"的离线红队用例 100% 通过（0 侧效应逃逸、每次拒绝有审计事件）；"已知残留"用例逐条登记且有部署边界说明 | 红队测试输出 + 残留清单 |
| G4.2 | 真实模型提示注入/目标劫持用例在 ≥3 次重复下 100% 不产生禁止副作用（拒绝或无害完成均可），逐次记录 | 红队报告 |
| G4.3 | `approval_mode=deny` 下所有 `requires_approval` 工具 100% 拒绝；默认工具集不含 `shell` / `http_get`；`python_exec` 的默认开启与 OS 级权限必须在 M4 中显式评审，给出"默认关闭 / 容器内启用 / 接受并记录"的结论与依据 | 审计测试 + 开关策略记录 |
| G4.4 | shell 子进程环境不含 API key；`http_get` 默认不注册；trace/report 中密钥被脱敏（`Config.redacted` 检查） | 秘密扫描测试 |
| G4.5 | 超大工具输出、超时子进程、递归式格式失败均被预算或超时截断，进程不崩溃且 trace 完整 | 资源耗尽测试 |
| G4.6 | benign 任务集 ≥10 条，误拒率被测量并报告；每条误拒有归因 | 误拒率报告 |
| G4.7 | 05 的威胁模型、强制点清单、部署建议与实现一致，无"文档声称已防御但代码未覆盖"的条目 | 文档-代码对照评审 |

**风险。**

| 风险 | 影响 | 缓解 |
|---|---|---|
| 红队集被针对性地修到全绿 | 安全假象 | 红队用例与实现分离管理；定期增补；真实模型套件与离线套件并用 |
| 提示注入无法根治 | 真实模型可能被诱导调用工具 | 安全靠工具层强制而非模型自律；权限最小化；审批与预算兜底 |
| 误拒影响可用性 | 安全压制能力 | 误拒率与合规率同时报告，见 04 |
| 沙箱边界被误读为生产级 | 部署事故 | 05 明确"进程级 + 路径级"；M5 前必须完成部署边界评审 |

**Non-goals。** 不做内核/容器隔离实现；不做形式化验证；不解决对齐（见 05）；不防御恶意工具实现（明确残留风险）。

## 8. M3 L3 脚手架：半自主长任务

**目标。** 在 M0 的预算、ASK、中断点脚手架上，让 agent 能在显式预算内处理超过单次 `max_steps` 的长任务：自设子目标、查询并申请预算、主动求助、从检查点恢复。目标是"自主性可控可审计"，不是"无人值守研究"。

**交付物。**

- 子目标提案机制：结构化记录（可被 critic/grader 审计），并纳入计划版本管理。
- 预算自管理：查询剩余预算、以受限方式申请增量；硬上限仍由运行时裁决，agent 不能自增。
- ASK 阻塞与恢复：信息不足时进入 `BLOCKED`，人类应答后恢复；无应答时显式结束。
- 检查点与恢复：中断后从已完成步骤继续，已完成步骤不重复执行副作用。
- 真实模型长任务报告：步数、预算利用、人工介入次数、安全检查。

**退出条件（gate）。**

| 编号 | 条件 | 证据 |
|---|---|---|
| G3.1 | 一个在 M0 默认预算下无法完成的长任务，在显式提高预算后可连续完成，期间无人工干预，且 token/墙钟不超新预算 | 长任务 run + 预算报告 |
| G3.2 | 至少一个任务中出现由 agent 自设并被采用的结构化子目标，事件可审计且替代了原计划中的步骤 | trace 事件 |
| G3.3 | 信息不足时产生 ASK 并进入 `BLOCKED`；提供应答后恢复；恢复运行不重复已完成步骤的副作用 | 阻塞/恢复测试 |
| G3.4 | agent 可查询预算并以结构化字段申请增量；申请被硬上限拒绝时显式失败；无自增预算路径 | 预算越权测试 |
| G3.5 | M4 红队套件保持全绿；在默认工具集（`shell` / `http_get` 关闭，`python_exec` 按 M4 评审结论处理）下，长任务无越界写入、无未审批副作用、无秘密外泄 | 安全回归 |
| G3.6 | 所有 run 在预算耗尽时 100% 停止并记录 `stop_reason`；无未记录的超时终止或无限循环 | 终止性审计 |

**风险。**

| 风险 | 影响 | 缓解 |
|---|---|---|
| 自主性提升带来的不可逆操作 | 数据损坏 | 审批默认拒绝；长任务默认关闭 shell/http；检查点前先做副作用审计 |
| 长任务成本失控 | 费用与时间不可控 | 预算硬上限 + 增量申请需显式裁决；逐任务成本报告 |
| 检查点状态与真实副作用不一致 | 恢复后重复写入 | 恢复时先对工作区做幂等检查；不一致时显式失败 |
| "自主性剧场"（agent 自问自答） | 指标虚高 | ASK 必须指向人类通道；自设子目标由 critic 审核并记录 |

**Non-goals。** 不做自我修改代码；不做开放式自主研究；不做多 agent 编排；不宣称 L4；不把 L3 脚手架等同于长期无人值守运行。

## 10. 依赖、审查与变更

- **依赖关系**：M0 是所有里程碑的前提；M1 提供评测台与真实基线；M2 依赖 M1 的采集能力；M4 依赖 M1 的真实模型红队与 M2 的数据审计能力；M3 依赖 M4 的安全门槛；M5 依赖 M3/M4 的全部证据。
- **并行规则**：不改变 gate 的探索性工作可以并行（如文档、工具扩展、性能），但不得在里程碑未通过时更新能力状态或对外发布能力结论。
- **审查规则**：每个 gate 通过必须附证据链接并归档；审查者至少一人不是该里程碑的实现者。
- **变更规则**：新增里程碑或调整 gate 时，先改 03、再同步 02/04/05 的相关事实；一次变更只改一处事实源，避免多文档漂移。
- **本文件的边界**：路线图描述"何时算完成"，不描述"如何实现"；实现方式见 02，取舍理由见 06，评测口径见 04，安全边界见 05。
